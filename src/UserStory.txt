User Story: Старт игры в консольном приложении

Как игрок,
я хочу запустить консольное приложение UNO и начать новую игровую сессию,
чтобы подготовить основу для одновременной игры в несколько сессий и дальнейшего сохранения состояния.

Контекст

На текущей итерации мы делаем только меню и сценарий старта, без реализации логики выбора первого игрока.

Acceptance Criteria

AC1 — Приложение запускается как Spring Boot CLI
  •  Есть Spring Boot приложение (Maven).
  •  При запуске появляется главное меню:
        1. Начать играть
        0. Выход

AC2 — Переход на меню старта игры
При выборе 1 показывается меню старта игры:
  •  1. Выбрать первого игрока рандомно
  •  2. Назначить первого игрока
  •  0. Назад

AC3 — Заглушки вместо бизнес-логики
  •  При выборе 1 или 2 приложение не падает непредсказуемо, а:
  •  либо печатает понятное сообщение Not implemented yet
  •  либо выбрасывает контролируемое исключение (например, UnsupportedOperationException("Not implemented yet"))
  •  После этого пользователь возвращается в меню старта игры (или приложение завершается — допустимо, но лучше возвращаться).

AC4 — Подготовка под “несколько игровых сессий”
  •  При старте игры создаётся идентификатор игровой сессии (пока в памяти), и он печатается в консоль, например:
Game started. SessionId=...
  •  Хранение в Postgres на этом шаге не требуется, но структура должна намекать, что оно будет (порт/репозиторий).

Definition of Done
  •  Код собирается и запускается одной командой
  •  Меню работает по критериям выше
  •  Есть минимальная структура пакетов под hexagonal
  •  Есть README с инструкцией запуска (1–3 команды)
