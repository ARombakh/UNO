  Class UNO
  Нельзя пользоваться бэкенд-приложениями, которые используют только одну игровую сессию
  Основные методы взаимодействия в main'e. При этом в классическом бэкенде пустой.
  Нужно перейти от процедурного программирования к асинхронному программированию.
  Инкапсулировать фукнции приложения в отдельные потоки, которые вызываются отдельно друг от друга (Spring)  
Где хранится состояние?
  В Class'е Uno и соданных внутри него классах (Player, Deck, DiscardPile)
  Проблема — отсутствие централизованного хранения
  Проблема — состояние игры хранится в Runtime приложения. Для сохранения нужна СУБД (Postgres)

  Выбор опции с помощью ввода в консоль
  Негибкое меню (каждый тип меню имеет отдельную функцию)
  Нельзя портировать вход на другой UI, отдельный от консоли
  Построить приложение т. о., чтобы был Pipeline выполнения, вызов, бизнес-логика, сохранение состояние, отдача ответа

  Выдаётся карта, которую нужно покрыть (DiscardPile)
  У игрока выводятся опции в виде имеющихся карт на руке
  Игрок выбирает свою карту, которой ходить, или пропускает ход (берёт карту)
    Если выбирает карту, проверяется возможность хода этой картой
